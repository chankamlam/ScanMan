# analysis/ —— 数据集分析脚本

本目录是**只读分析工具**：不修改 `data/` 下的任何文件，也不参与训练流程。
原流水线（`scripts/build_dataset.py`、`src/utils.py`、`configs/config.yaml`）**一行未改**。

## 这两个脚本解决什么问题

项目原本**没有任何数据分析和绘图代码**（全仓库搜索 `matplotlib` / `seaborn` / `plot`
只有依赖声明，没有实际调用）。本目录补齐了「数据处理环节分析」和「探索性数据分析」
两块内容。

| 脚本 | 作用 | 产出 |
|------|------|------|
| `audit_data.py` | 数据质量审计：缺失 / 异常 / 重复，覆盖原始数据与预处理后数据两段 | `reports/tables/audit_raw.json`<br>`reports/tables/audit_processed.json` |
| `plot_eda.py` | 探索性数据分析可视化，共 **20 张图** | `reports/figures/*.png`<br>`reports/tables/token_stats.json` |

## 运行方法

```powershell
cd F:\NLP_SZ\ScanMan
$env:PYTHONIOENCODING = "utf-8"
$PY = "D:\anaconda\envs\PYTHON_NLP\python.exe"

# 第一步：质量审计（约 3~5 分钟，需流式读完 1.16 GB parquet）
& $PY analysis\audit_data.py

# 第二步：生成全部图表（约 2~3 分钟）
& $PY analysis\plot_eda.py
```

> `plot_eda.py` 依赖第一步产出的 JSON，**必须先跑 `audit_data.py`**。
> 若缺少会直接报错并提示。

## 实现上几个值得注意的点

**1. 流式读 parquet 而不是一次载入**
```python
pf = pq.ParquetFile(fp)
for batch in pf.iter_batches(batch_size=64, columns=cols):
```
CVEfixes 单个 parquet 400~550 MB，个别代码字段达 55 MB，
`pq.read_table()` 全表解压后可能几 GB，容易内存溢出。

**2. 缺失检查必须查三种情况**
```python
if v is None:                     # 真正的空值
elif v.strip() == "":             # 空字符串
elif v.strip().lower() == "nan":  # 字符串 "nan"（severity 字段有 4,799 条）
```
只查 `isna()` 会漏掉 2,911 条空字符串 + 4,799 条 `"nan"`。

**3. 长度类图表一律用对数轴**
分布右偏 5 个数量级（中位 233 vs 最大 55,330,596），
线性轴下所有信息都会挤在左边一个像素里。

**4. ★ 字符/词元比运行期实测，不硬编码**
```python
CHARS_FOR_512 = int(MAX_LENGTH * measured_ratio)   # 实测 2.28 → 1168
```
这是本项目一个真实教训：早期用经验值 3.8 字符/词元，
算出"19.4% 的样本超窗"；实测比值是 2.28，修正后是 **27.0%**，
与直接分词测量的 **26.6%** 吻合。**一个经验值让结论偏低了 7 个百分点。**

**5. matplotlib 版本兼容**
- matplotlib ≥ 3.9 把 `boxplot()` 的 `labels` 改名 `tick_labels`，脚本做了 try/except 双向兼容
- 中文字体用 `Microsoft YaHei`，并设 `axes.unicode_minus = False` 避免负号变方块

**6. 每次运行先清空旧图**
```python
for p in FIG_DIR.glob("*.png"):
    p.unlink()
```
避免改了脚本之后旧图还留在目录里、被误当成新结果。

**7. 分词器自动定位**
依次尝试三个位置（本仓库 → 同级原始工程 → `F:\NLP`），
都找不到才降级并打印警告，且**跳过**依赖它的图（而不是画出错误的图）。
