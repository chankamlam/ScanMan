# 数据集说明（Dataset Card）

本目录记录 ScanMan 项目所使用的漏洞数据集，包括来源、许可证、字段、规模与构建方式。

---

## 一、总览

| 数据源 | 原始数据 | 检测样本（二分类） | 分类样本（CWE 多分类） | 类别数（含 OTHER） |
|--------|----------|-------------------|----------------------|--------|
| CVEfixes | 13,000 条 CVE 修复记录 | **18,925** | **7,291** | 41 |
| BigVul | 223,003 个函数 / 3,754 CVE | **174,161** | **7,346** | 27 |
| DiverseVul | 523,956 个函数 / 933 项目 | **505,690** | —（无 CWE 字段） | — |
| CodeXGLUE | 27,318 个函数 | **27,254** | —（仅二分类） | — |
| **merged** | 四源合并 | **539,124** | **14,637** | 41 |

> 「类别数」取的是各 `data/processed/*_classification_label_map.json` 的 `num_labels`，
> **已含长尾合并出来的 `OTHER` 类**（所以是 40 种 CWE + OTHER = 41）。
> 演示分类模型用的是 `scripts/relabel_classes.py --top-k 27` 二次打标后的 **28 类**
> （见 [`09_命令参考.md`](./09_命令参考.md) 第 2 节）。

**磁盘占用**：`data/processed` 1.9 GB；`data/raw` 约 2.2 GB（**四源齐全时**），
本仓库当前只放了 CVEfixes，实际约 1.2 GB。

> **下载与构建**：`scripts/download_data.py` 目前只提供 CVEfixes 的下载（其余数据源
> 需自行准备 `data/raw/` 下的原始文件）；四个构建器与 `merged` 都在
> `scripts/build_dataset.py` 的 `BUILDERS` 中注册，构建产物统一写入 `data/processed/`。
> 演示用的 28 类分类数据是 `scripts/relabel_classes.py --source merged --top-k 27`
> 在 `merged` 分类数据上重标得到的（27 个 CWE + `OTHER`），文件前缀为 `merged_top27`。

## 二、各数据集详情

### 1. CVEfixes ⭐ 推荐

- **论文**：Bhandari, Nanz, Sabetta. *CVEfixes: Automated Collection of Vulnerabilities and Their Fixes from Open-Source Software.* MSR 2021.
- **来源**：从 NVD 抓取 CVE 记录，关联到开源项目的修复提交，抽取代码 diff 还原出修复前/后代码。
- **官方版本**：v1.0.8（截至 2024-07-23），覆盖 12,107 个修复提交、4,249 个项目。
- **本仓库使用**：HuggingFace `hitoshura25/cvefixes` —— 官方 SQL dump 的**函数级衍生版**，13,000 行，**23 个字段**
  （字段清单见 `docs/01` §1.2）。
- **下载**：
  - 官方全量（12 GB SQL dump）：https://zenodo.org/records/13118970
  - 官方工具链：https://github.com/secureIT-project/CVEfixes
  - 函数级版（本仓库）：https://huggingface.co/datasets/hitoshura25/cvefixes
- **原始字段**：`cve_id`, `hash`, `repo_url`, `cve_description`, `cvss2_base_score`, `cvss3_base_score`, `severity`, `cwe_id`, `cwe_name`, `cwe_description`, `commit_message`, `language`, `file_paths`, `diff_stats`, `diff_with_context`, `vulnerable_code`, `fixed_code`, `security_keywords` 等。
- **标签来源**：
  - 检测 → `vulnerable_code`(label=1) / `fixed_code`(label=0)
  - 分类 → `cwe_id`（269 个原始取值）
- **许可证**：MIT
- **特点**：规模适中、正负样本接近均衡、CWE 标注来自 NVD 官方，最适合入门与快速迭代。

### 2. BigVul

- **论文**：Fan, Li, Wang, Nguyen. *A C/C++ Code Vulnerability Dataset with Code Changes and CVE Summaries.* MSR 2020.
- **来源**：3,754 个 CVE、348 个项目的修复提交，抽取 `func_before`（漏洞版本）与 `func_after`（修复版本）。
- **下载**：https://github.com/ZeoVan/MSR_20_Code_vulnerability_CSV_Dataset · https://huggingface.co/datasets/bstee615/bigvul
- **原始字段**：`CVE ID`, `CWE ID`, `codeLink`, `commit_id`, `commit_message`, `func_before`, `func_after`, `lang`, `project`, `vul`
- **标签来源**：
  - `vul=1` → `func_before` 是漏洞函数（label=1），同时把 `func_after` 作为 label=0 的**难负样本**加入
  - `vul=0` → 同一提交中的无关函数，视为安全（label=0）
  - 分类 → `CWE ID`
- **许可证**：学术研究用途
- **特点**：规模大（17.4 万），但漏洞/安全比例约 1:16，严重不平衡。适合验证不平衡处理策略。

### 3. DiverseVul

- **论文**：Chen, Ding, Alowain, Chen, Wagner. *DiverseVul: A New Vulnerable Source Code Dataset for Deep Learning Based Vulnerability Detection.* RAID 2023.
- **来源**：爬取安全问题网站，提取修复提交，覆盖 150 个 CWE、933 个项目。
- **下载**：https://github.com/wagner-group/diversevul · https://huggingface.co/datasets/starsofchance/My_DiverseVul
- **原始字段**：`project`, `commit_id`, `target`（0/1）, `func`, `idx`
- **标签来源**：`target`
- **许可证**：学术研究用途
- **特点**：目前最大的公开漏洞函数数据集（50.6 万）。**注意**：本 HF 镜像版本不含 CWE 字段，仅可用于检测任务。若需要 CWE，请从 GitHub 原始版本获取。

### 4. CodeXGLUE Defect Detection

- **论文**：Lu et al. *CodeXGLUE: A Machine Learning Benchmark Dataset for Code Understanding and Generation.* NeurIPS 2021.（原始数据来自 Devign）
- **来源**：FFmpeg、QEMU 等 4 个 C 项目的函数级人工标注。
- **下载**：https://github.com/microsoft/CodeXGLUE/tree/main/Code-Code/Defect-detection · https://huggingface.co/datasets/google/code_x_glue_cc_defect_detection
- **原始字段**：`func`, `target`（0/1）
- **许可证**：C-UDA
- **特点**：规模小但标注质量高，是漏洞检测领域的**标准对比基线**，论文中的 SOTA 指标都以此为准。

## 三、统一后的数据格式

### 文件命名
```
data/processed/
├── <source>_detection_train.jsonl / _val.jsonl / _test.jsonl
├── <source>_classification_train.jsonl / _val.jsonl / _test.jsonl
├── <source>_detection_label_map.json
├── <source>_classification_label_map.json
└── <source>_stats.json
```

### 记录字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | str | 唯一标识，如 `CVE-2023-4432-vuln` / `bigvul::<commit>::before` |
| `code` | str | 源码片段。**落盘时**已按 `data.max_code_chars` 做头尾截断，**上限 20,000 字符**（实测最长 20,035，多出的是截断标记）；8,000 是 `model.max_code_chars`，在送 tokenizer **之前**才生效，不是这个字段的属性 |
| `label` | int | 检测：0/1；分类：CWE 类别 id |
| `cwe` | str | 原始 CWE 编号，如 `CWE-79`（安全样本为空） |
| `cwe_name` | str | CWE 英文全称 |
| `source` | str | 数据源标识 |
| `language` | str | 编程语言 |
| `project` | str | 所属开源项目 |
| `group_id` | str | 防泄漏分组键（CVE + commit hash） |
| `code_hash` | str | 代码内容的 MD5，用于去重 |

### 标签映射示例（`cvefixes_classification_label_map.json`）

```json
{
  "task": "classification",
  "num_labels": 41,
  "id2name": {
    "0": "CWE-79",   "1": "CWE-125", "2": "CWE-89",  "3": "CWE-20",
    "4": "CWE-787",  "5": "CWE-119", "6": "CWE-22",  "7": "CWE-476",
    "...": "...",
    "40": "OTHER"
  }
}
```

`num_labels = 保留的 CWE 类别数 + 1`（末尾 `OTHER` 用于承接长尾类别）。

## 四、构建流程（`scripts/build_dataset.py`）

```
原始数据 (parquet / jsonl)
   ↓ ① 字段归一化：统一成 id / code / label / cwe / group_id
   ↓ ② 长度过滤：丢弃 < 30 字符的碎片
   ↓ ③ 头尾截断：> 20,000 字符时按 6:4 保留头尾（防止超长文件撑爆内存）
   ↓ ④ MD5 去重：同一段代码只保留一份
   ↓ ⑤ 按 group_id 分组划分 8:1:1（防数据泄漏）
   ↓ ⑥ 分类任务：CWE 频次统计 → 样本量 < 30 的合并为 OTHER → 取 Top-40
统一 JSONL + 标签映射 + 统计信息
```

**关键：为什么按 `group_id` 而不是按样本随机划分？**
CVEfixes/BigVul 中同一 CVE 的「漏洞版本」与「修复版本」往往只差几行。若随机划分，测试集里会出现训练集的近似副本，指标会虚高到 0.99。以 CVE+commit 为单位划分后，测试集才是真正的"未见过的漏洞"。
