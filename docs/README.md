## 目录里的其他资产

| 路径 | 说明 |
|------|------|
| `check_all.bat` | 一键跑「环境自检 → `pytest tests/` → 预处理断言 → 冒烟训练 → 批量推理」 |
| `test_cases/test_preprocess.py` | 预处理断言（清洗 / 截断 / CWE 规范化 / 防泄漏划分 / 标签映射） |
| `test_cases/detection_test_cases.jsonl` | 人工写的检测用例（漏洞 + 安全，含正负对） |
| `test_cases/classification_test_cases.jsonl` | 人工写的分类用例（覆盖高频 CWE，跨 C/PHP/Python） |
| `test_cases/out_detection*.jsonl` | 批量推理的实测输出，用于看输出格式 |

> ⚠️ **人工用例只是"人眼看得懂的小抄"**，用来快速看输出格式、直观感受，
> **不作为验收标准**。真正的测试集是 `data/processed/<source>_detection_test.jsonl`
> 与 `data/processed/<source>_classification_test.jsonl`，用
> `python scripts/evaluate.py --checkpoint ... --input ... --sweep` 评估。

## 最快的验证方式

> ⚠️ **先决条件（新克隆的仓库没有这些，`.gitignore` 把它们排除在版本库外）：**
>
> | 需要 | 位置 | 怎么来 |
> |---|---|---|
> | 基础模型 | `models/microsoft__codebert-base/` | `python scripts/download_model.py --models codebert` |
> | 训练数据 | `data/processed/cvefixes_detection_*.jsonl` | `python scripts/build_dataset.py --source cvefixes`（需先下原始数据） |
>
> 缺任一项，脚本会在第 4 步冒烟训练时失败 —— `check_all.bat` 开头会先做这项检查并给出提示。

```bat
cd /d <项目根>\ScanMan
docs\check_all.bat
```

它依次跑：环境自检 → `pytest tests/` → 预处理断言 → 冒烟训练（64 条样本 1 轮）
→ 批量推理，最后打印 `ALL CHECKS PASSED`。冒烟模型的准确率数字**没有意义**，
它只证明「数据能读、模型能建、能训练、能保存、能加载、能推理」这条链路是通的。

第 5 步用的是第 4 步刚训出来的 `outputs/quickstart/best`，所以**必须从第 1 步完整跑下来**；
仓库里那份 `outputs/quickstart/` 只剩配置和标签映射，没有权重，不能拿来单独跑推理。

## 文档里的实测口径

文档中的历史实测数字来自当时的本机环境，属于**实验记录**，不代表当前推荐配置：

| | 历史训练环境 |
|---|---|
| 解释器 | Python 3.12（conda `py312`） |
| torch | 2.14.0 + cu130 |
| GPU | RTX 3060 Laptop 6 GB |

当前推荐的运行方式是 README「快速开始」里的独立虚拟环境（Python 3.12）：
有 NVIDIA GPU 时安装 CUDA 版 PyTorch，无 GPU 时自动使用 CPU。

**当前演示报告所用的模型**（详见 `../README.md`「模型产物与已有实验」）：

| 用途 | 检查点 |
|------|--------|
| 检测模型 | `outputs/merged_detection_codebert/best` |
| CWE 分类模型 | `outputs/merged_top27_codebert_e20/best` |

检测模型测试集（阈值 0.5）Precision 0.3774 / Recall 0.6779 / F1 0.4848 / ROC-AUC 0.8717；
分类模型 28 类测试集 Accuracy 0.3333 / Macro-F1 0.2392 / Top-3 0.6041 / Top-5 0.7438。
检测检查点保存的阈值是 **0.67**（按验证集 F1 选择），与上表的 0.5 口径不同，不能混用。
