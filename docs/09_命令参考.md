# 命令参考

项目里全部脚本的命令与参数速查。[`../README.md`](../README.md) 负责回答
「这个项目是什么、怎么最快看到效果」，**具体的命令细节都在本文件**。

三条通用约定：

- 除特别注明外，命令都在**项目根目录**执行。
- 路径类参数（`--output` / `--checkpoint` / `--model` / `--run` 等）传相对路径时，
  **按项目根目录解析**，与从哪个目录启动无关（`src/config.py` 的 `resolve_path`）。
  例外：`scan_project.py` 的位置参数 `path` 按**当前工作目录**解析。
- 下面的 `python` 指你环境里的解释器，见第 1 节。

## 1. 环境准备

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m pip install flask
python scripts/check_env.py
```

Linux / macOS 的激活命令是 `source .venv/bin/activate`。

> ⚠️ `requirements.txt` **不含 flask**，但 Web 后端（`scripts/serve.py`）和
> `tests/test_serve.py` 需要它，所以要单独装一行。

`requirements.txt` 已配置 PyTorch CUDA 13.0 的额外下载源。用 NVIDIA GPU 时确认驱动与装到的
PyTorch 匹配：

```bash
python -c "import torch; print(torch.__version__); print(torch.cuda.is_available())"
```

没有可用 CUDA 时自动退回 CPU，训练会明显变慢。tree-sitter 核心库和语言包已固定版本，
安装时保留这些版本约束。

`scripts/check_env.py` 不需要 `--help`，直接跑就是自检：Python 版本、依赖、
CUDA/GPU、`data/raw`、`data/processed` 逐项打 `[ OK ]` / `[FAIL]`。

## 2. 数据：下载与构建

### 2.1 下载

```bash
python scripts/download_data.py --list                      # 看有哪些数据集
python scripts/download_data.py --datasets cvefixes         # 下载（目前只提供 cvefixes）
python scripts/download_model.py --list                     # 看有哪些基础模型
python scripts/download_model.py --models codebert          # 下载 CodeBERT
```

| 参数 | 作用 |
| --- | --- |
| `--datasets 名字` | 逗号分隔，或 `all`。当前实际可下载的只有 `cvefixes` |
| `--models 名字` | 逗号分隔，或 `all` |
| `--mirror hf-mirror` | 换下载源（`huggingface` / `hf-mirror` / 自定义 `https://` 前缀），网络慢时用 |
| `--raw-dir`（仅 download_data） | 覆盖数据集落盘目录 |
| `--out`（仅 download_model） | 覆盖模型落盘目录 |

模型默认下载到 `models/microsoft__codebert-base/`（目录名把 `/` 换成 `__`）。
`models/` 被 `.gitignore` 排除，**新克隆的仓库没有**，需要自己跑一次。

> 只做推理时**不强制**要这份本地模型：检测检查点的 `config.yaml` 写的是 HF 仓库名
> `microsoft/codebert-base`，会走 `~/.cache/huggingface/` 缓存；分类检查点写的是本地路径，
> 找不到时由 `scripts/predict.py` 的 `_resolve_backbone` 还原成仓库名兜底。
> 但每次都向 HuggingFace 发一次请求，**要彻底离线就先把它下下来**。

### 2.2 构建数据集

```bash
python scripts/build_dataset.py --source cvefixes                    # 默认同时建检测和分类
python scripts/build_dataset.py --source cvefixes --task detection   # 只建检测
python scripts/build_dataset.py --source merged                      # 四源合并
python scripts/relabel_classes.py --source merged --top-k 27         # 分类标签归并到 28 类
```

支持的数据源及原始文件布局：

| `--source` | 预期原始文件 | 任务支持 |
| --- | --- | --- |
| `cvefixes` | `data/raw/cvefixes/train-*.parquet` | 检测、CWE 分类；下载源为 `hitoshura25/cvefixes` |
| `bigvul` | `data/raw/bigvul/{train,val,test}.parquet` | 检测、CWE 分类 |
| `diversevul` | `data/raw/diversevul/{train,valid,test}.jsonl` | 当前适配器只读取检测标签 |
| `codexglue` | `data/raw/codexglue/{train,val,test}.parquet` | 当前适配器只读取检测标签 |
| `merged` | 上述四个目录 | 合并已有记录后统一去重，再构建检测和分类数据 |

后三个数据源需要自行按构建器要求准备字段与文件，`download_data.py --datasets all`
目前也只下载 CVEfixes。构建器遇到缺失源文件会警告并继续，构建 `merged` 前应核对四个源是否齐全。

`relabel_classes.py` 在**已有**分类数据上重新编码标签，输出前缀默认 `{source}_top{top-k}`，
保留 Top-27 CWE，其余归入 `OTHER`；不改变源码、样本数及原有 train/val/test 划分。
`merged_top27` 是重标后的**文件前缀**，不是 `build_dataset.py` 的数据源名。

常用参数：`--task detection|classification|both`、`--raw-dir`、`--out-dir`、
`--max-samples`（调试用；注意它是**整条记录流**的上限——构建 `merged` 时四个源**合计**
到该条数就停，不是每个源各保留这么多）。

### 2.3 处理后的产物

```text
data/processed/
├── <source>_<task>_train.jsonl
├── <source>_<task>_val.jsonl
├── <source>_<task>_test.jsonl
├── <source>_<task>_label_map.json
└── <source>_stats.json
```

JSONL 每行一条样本，含 `id`、`code`、`label`、`cwe`、`cwe_name`、`source`、`language`、
`project`、`group_id` 等字段；启用去重时还有 `code_hash`。

- 检测标签 `0=safe`、`1=vulnerable`；分类只用有 CWE 标注的漏洞样本，标签编号由对应的
  `label_map.json` 定义。
- 默认过滤不足 30 字符的代码，对超过 20,000 字符的做头尾截断，再按代码 MD5 去重。
- 默认按 `group_id` 以 8:1:1 划分。CVEfixes 按 CVE + commit 分组，BigVul 按 commit 分组；
  DiverseVul 和 CodeXGLUE 当前是样本级分组键。**该机制不等于完成了跨源近重复或跨项目泄漏审计。**
- 默认分类配置保留最多 40 个 CWE，不足 30 条的类别及其余长尾归入 `OTHER`。

## 3. 训练

```bash
python scripts/train.py --task detection      --source cvefixes   --model models/microsoft__codebert-base --run-name cvefixes_detection_local
python scripts/train.py --task classification --source cvefixes   --model models/microsoft__codebert-base --run-name cvefixes_classification_local
```

已生成合并数据时：

```bash
python scripts/train.py --task detection      --source merged     --model models/microsoft__codebert-base --run-name merged_detection_local
python scripts/train.py --task classification --source merged_top27 --model models/microsoft__codebert-base --epochs 20 --run-name merged_top27_local
```

只验证流程（不评价效果）：

```bash
python scripts/train.py --task detection --source cvefixes --model models/microsoft__codebert-base \
    --epochs 1 --batch-size 4 --max-length 128 --max-train-samples 200 --max-eval-samples 100 \
    --run-name smoke_local --cpu
```

> ⚠️ **一定要传 `--model` 指向本地路径。** 不传就用 `configs/config.yaml` 里的
> `microsoft/codebert-base`（HF 仓库名），会联网下载约 1 GB —— 而本地 `models/` 里
> 往往已经有同一份权重了。详见 `02` 文档排错手册。

| 参数 | 作用 |
| --- | --- |
| `--task` | `detection` / `classification` |
| `--source` | 数据源前缀，对应 `data/processed/<source>_<task>_*.jsonl` |
| `--model` | 覆盖预训练模型名或本地路径 |
| `--run-name` | 实验名，默认 `<数据源>_<任务>_<模型名>` |
| `--epochs` / `--batch-size` / `--lr` / `--max-length` | 训练超参 |
| `--max-train-samples` / `--max-eval-samples` | 限制样本量，调试用 |
| `--imbalance` | `none` / `weighted_loss` / `balanced_sampler` |
| `--log-steps` / `--eval-steps` / `--num-workers` / `--output-dir` | 日志与 IO |
| `--cpu` | 强制 CPU（等价 `--device cpu`，保留给老命令） |

参数优先级为：**命令行 > `configs/config.yaml` > `src/config.py` 的 `DEFAULTS`**。
`--epochs` 是轮数上限，实际可能提前停止；`best/` 保存验证集指标最优的检查点。

## 4. 推理与评估

```bash
# 单段代码
python scripts/predict.py --checkpoint outputs/cvefixes_detection_local/best \
    --code "void f(char *s){ char buf[10]; strcpy(buf, s); }"

# 整个文件作为一条输入（要逐函数处理请用 scan_project.py）
python scripts/predict.py --checkpoint outputs/cvefixes_detection_local/best --file path/to/x.c

# 批量推理
python scripts/predict.py --checkpoint outputs/cvefixes_detection_local/best \
    --input data/processed/cvefixes_detection_test.jsonl --output outputs/preds_local.jsonl

# 在带标签的数据集上评估
python scripts/evaluate.py --checkpoint outputs/cvefixes_detection_local/best \
    --input data/processed/cvefixes_detection_test.jsonl --sweep
python scripts/evaluate.py --checkpoint outputs/cvefixes_classification_local/best \
    --input data/processed/cvefixes_classification_test.jsonl
```

分类检查点也可以传给 `predict.py`，输出 CWE 和最多 5 个候选；**分类模型本身不判断代码是否安全**。

| 参数 | 作用 |
| --- | --- |
| `--checkpoint` | 微调后的模型目录（含 `best/`） |
| `--code` / `--file` / `--input` | 三种输入形态，三选一 |
| `--output` | 批量输出的 JSONL |
| `--threshold` | 检测任务的判定阈值，默认读检查点自带的 `threshold.json` |
| `--sweep`（仅 evaluate） | 额外打印阈值扫描表 |
| `--max-samples`（仅 evaluate） | 只评估前 N 条 |

## 5. 阈值调优

```bash
python scripts/tune_threshold.py --run outputs/cvefixes_detection_local --split val --criterion f1 --write
python scripts/tune_threshold.py --run outputs/merged_detection_codebert --split val --criterion recall --target-recall 0.90 --write
```

| 参数 | 作用 |
| --- | --- |
| `--run` | 训练输出目录，如 `outputs/cvefixes_detection_6ep` |
| `--split` | `val`（默认，避免偷看测试集）/ `test` |
| `--criterion` | **`recall`（默认）**：满足目标召回率的前提下精确率最高，适合漏报比误报严重的场景；`f1`：F1 最大，适合误报也要控的场景 |
| `--target-recall` | 仅 `--criterion recall` 时生效，默认 `0.90` |
| `--write` | 把选出的阈值写进 `<run>/best/threshold.json` |

> ⚠️ **两个 criterion 选出来的阈值差别非常大。** 同一个演示检测模型上，实测：
>
> | criterion | 阈值 | 验证集 precision | 验证集 recall |
> |---|---|---|---|
> | `f1` | 0.67 | 0.459 | 0.591 |
> | `recall`（默认，目标 0.90） | 0.245 | 0.219 | 0.902 |
>
> 阈值越低命中越多、误报也越多。**调完阈值必须重新跑 `check_fixture.py`**：
> 夹具的"30/30 全判对"是在 0.67 下成立的，切到 0.245 会有 3 个原本安全的函数被淹成可疑。

该脚本读取训练保存的 `probs_<split>.npy` 与 `labels_<split>.npy`
（**只读概率，不读 logits**，找不到概率文件会直接 `FileNotFoundError`）；
Git 里的指标 JSON 不能代替这些数组。

检测判定采用 `prob_vulnerable >= threshold`。优先级为：
**显式 `--threshold` > 检查点里的 `threshold.json` > 默认 `0.5`**。
阈值应在验证集上选，再在测试集上评价。

## 6. 项目扫描

```bash
# 不加载模型，只抽取函数（只需 Python 依赖）
python scripts/scan_project.py demo_verified/ --output outputs/scan_extract.json

# 只检测
python scripts/scan_project.py demo_verified/ \
    --checkpoint outputs/merged_detection_codebert/best --output outputs/scan_detection.json

# 检测 + CWE 分类（生成 Web 的「示例报告」）
python scripts/scan_project.py demo_verified/ \
    --checkpoint outputs/merged_detection_codebert/best \
    --classifier outputs/merged_top27_codebert_e20/best \
    --output web/public/sample_report.json
```

把 `demo_verified/` 换成目标项目目录或单个源文件即可。检测和分类是**两个独立检查点**；
`--classifier` 必须与 `--checkpoint` 一起提供。

| 参数 | 作用 |
| --- | --- |
| `path` | 要扫描的目录或单个文件（**按当前工作目录解析**） |
| `--output` | 报告输出路径，默认 `outputs/scan_result.json`（按项目根解析） |
| `--checkpoint` | 检测模型目录；不给则只抽取不推理 |
| `--classifier` | 分类模型目录；给定时只对**检测命中**的函数再跑一级 CWE 分类 |
| `--threshold` | 临时覆盖检测阈值 |
| `--device` | `cpu` / `cuda` / `mps` / `cuda:1`，默认自动 |
| `--batch-size` | 推理批大小，默认 16 |
| `--max-file-size` | 单文件字节上限，默认 2,000,000 |
| `--outer-only` | 排除嵌套函数与闭包；类方法仍按深度 0 计入 |
| `--skip-dir NAME` | 额外跳过指定目录名，可重复传入 |
| `--no-skip` | 关闭默认目录过滤 |
| `--no-code` | 不把函数源码写进报告 |

默认跳过隐藏目录以及 `node_modules`、`vendor`、虚拟环境、构建产物等目录。

只抽取模式下报告**没有执行漏洞检测**，其中可疑函数计数为 0 **不代表代码安全**。

## 7. Web 后端与前端

### 7.1 后端

```bash
python scripts/serve.py
```

监听 `127.0.0.1:8000`，与 `web/vite.config.ts` 的代理目标一致。

| 参数 | 作用 |
| --- | --- |
| `--detector 路径` | 检测模型目录，默认 `outputs/merged_detection_codebert/best` |
| `--classifier 路径` | 分类模型目录，默认 `outputs/merged_top27_codebert_e20/best` |
| `--device` | 推理设备，默认自动 |
| `--port 8000` | 监听端口，**改了要同步改 Vite 的 proxy** |
| `--batch-size 16` | 推理批大小 |

模型在后台线程加载，耗时取决于设备及模型文件大小。未就绪时前端「开始检测」按钮禁用。
服务只绑 `127.0.0.1`，不对外网开放；同一时刻只接受一个扫描任务，重复提交收到 409 而不是排队。

| HTTP 接口 | 请求与返回 |
| --- | --- |
| `GET /api/health` | 模型状态 `loading` / `ready` / `error`，以及设备、检查点、阈值等 |
| `POST /api/scan` | 接收 `files` 数组（每项 `client_id` / `name` / `content_b64`），返回 `report` 和逐文件 `uploads` 回执 |

请求体上限 64 MiB；模型未就绪 503，上传参数错误 400，已有扫描进行中 409。
上传的文件写在**临时目录**里，扫描结束后删除——报告里保留了函数源码，所以扫描结果本身不会丢，
但**原始上传件（含被跳过的）不会留档**。

### 7.2 前端

```bash
cd web
npm install
npm run dev          # 默认 http://localhost:5173
```

只展示报告时不需要 Python、GPU 或模型权重。页面初始为空，点「示例报告」即可看现成结果，
也可以直接用下列地址打开：

| 地址 | 内容 |
| --- | --- |
| `http://localhost:5173/?r=sample_report.json` | 检测 + CWE 分类 |
| `http://localhost:5173/?r=sample_report_detection_only.json` | 仅检测（没有 CWE） |
| `http://localhost:5173/?r=sample_report_extract_only.json` | 仅抽取函数（**没有任何判定**） |

自定义报告放进 `web/public/`，通过 `?r=文件名.json` 选择；文件名须使用英文字母、数字、
下划线、连字符或点。构建与检查：

```bash
npm run typecheck
npm run build
npm run preview
```

## 8. 自检与测试

```bash
python -m pytest tests/ -v              # 抽取 / 级联 / 预测指标 / Web 接口，桩推理器，秒级
python docs/test_cases/test_preprocess.py   # 数据预处理断言
python scripts/check_fixture.py         # 复验 demo_verified/ 夹具是否仍全部判对
python scripts/check_env.py             # 环境自检
```

`pytest tests/` **不需要模型权重**，是验证整条链路（含 Web 后端落盘、回执对齐、并发锁）
最省事的手段。`check_fixture.py` 需要两个检查点，退出码 0=全对 / 1=有不准 / 2=环境问题。

`docs/check_all.bat` 一键串起「环境自检 → `pytest` → 预处理断言 → 冒烟训练 → 批量推理」，
前置条件（`models/` 与 `data/processed/`）不齐时会先提示。

## 9. 全部脚本一览

| 脚本 | 职责 |
| --- | --- |
| `download_data.py` / `download_model.py` | 下载数据集、基础模型 |
| `build_dataset.py` / `relabel_classes.py` | 数据构建、分类标签归并 |
| `train.py` | 训练并保存验证集最优检查点 |
| `predict.py` | `VulnPredictor` 及单条 / 批量推理命令 |
| `evaluate.py` / `tune_threshold.py` | 指标评估、检测阈值选择 |
| `scan_project.py` | 函数抽取、两级推理、报告汇总 |
| `serve.py` | Flask 后端：模型状态、文件上传扫描、报告返回 |
| `check_fixture.py` | 复查 `demo_verified/` 夹具在当前检查点下是否仍全部判对 |
| `check_env.py` | 环境自检 |
| `spike_align.py` | 分布对比实验（`--no-model` 可跳过模型段，只做结构统计） |

`src/` 侧的职责见 README「它是怎么工作的」。
