# 项目交接与迁移指南

> **场景**：把整个项目文件夹同步给另一个人，对方拿到后能自己跑训练、继续做实验。
>
> 覆盖四件事：**同步什么 / 对方怎么验收 / 有哪些现成参数 / 换机器后会踩哪些坑**。
>
> 权威口径见根目录 [`../README.md`](../README.md)。本文中的体积、报错、指标来自历史实测，
> 换机器后以本机实际结果为准。

---

## 0. 一句话结论

代码、配置和文档都很小（< 5 MB），**体积都在数据和模型上**：`data/` 约 3.1 GB
（`processed` 1.9 GB + `raw` 只放 CVEfixes 时 1.2 GB）、`models/` 约 0.5 GB、
每个带权重的训练产物约 0.5 GB。这些目录都在 `.gitignore` 里，
clone 仓库不会带上，需要单独同步或用脚本重新准备。

| 对方拿到什么 | 能做什么 | 不能做什么 |
|--------------|----------|------------|
| 完整文件夹（代码 + `models/` + `data/` + `outputs/`） | 环境自检、推理、继续训练、换数据源/换模型做对比实验、跑 Web 前端 | 从已训练检查点"无缝续训"（见第 4 节） |
| 最小集（代码 + `models/` + `data/processed/` + 1 个检查点） | 上面除"改清洗规则重新构建数据集"之外的全部 | 同上 |

## 1. 同步清单

### 1.1 各部分的内容与体积

| 内容 | 体积 | 必须同步？ | 说明 |
|------|-----:|:----------:|------|
| `src/` `scripts/` `configs/` `tests/` `web/` `README.md` `requirements.txt` | < 5 MB（不含 `node_modules`） | ✅ 必须 | 全部代码。**代码里零硬编码路径**，换目录直接能用 |
| `docs/` | 约 280 KB | ✅ 必须 | 本目录的全部文档 + 测试用例 + 一键脚本 |
| `demo_verified/` | < 1 MB | ✅ 建议 | 唯一的小样例目录：`test_NN.c` + `TRUTH.json`，演示与夹具回归用 |
| `models/microsoft__codebert-base/` | **约 477 MB** | ✅ 强烈建议 | 带了就不用联网。**本仓库当前没有这个目录**，见 4.3 |
| `data/processed/` | **约 1.9 GB** | ⚠️ 二选一 | 带了可直接训练，不用重新构建 |
| `data/raw/` | 四源齐全约 **2.2 GB**<br>只放 CVEfixes 时约 1.2 GB | ⚠️ 二选一 | 带了对方才能改清洗规则重新构建数据集 |
| `outputs/<run>/`（带权重的） | **每个约 0.5 GB** | ✅ 建议 | 训练好的检查点，对方可直接推理（见第 3 节）。**13 个里只有 7 个带权重**，另外 6 个只剩配置和标签映射 |
| `web/node_modules/` | 数百 MB | ❌ 不要 | 对方在 `web/` 执行 `npm install` 自动重建 |

> `data/raw` 与 `data/processed` **不必都带**：
> 只带 `processed` → 对方能立刻训练，但不能改清洗逻辑；
> 只带 `raw` → 对方要先跑 `build_dataset.py` 才能训练，但能改清洗逻辑。
>
> ⚠️ **只带 `raw` 时注意**：`build_dataset.py --source merged` 缺源文件时只打
> `log.warning` 继续跑，不会报错 —— 四个源不齐时 `merged` 会**静默退化**成实际存在的那些源
> （只放了 CVEfixes 就退化成 CVEfixes），产出的样本数与"四源合并"的口径对不上。
> 要确认，跑完看 `<source>_stats.json` 里的来源统计。
>
> `data/raw/`、`data/processed/`、`models/`、`outputs/*/*.bin`、`outputs/*/*.npy`、
> `web/node_modules/` 都被 `.gitignore` 排除，不会进版本库。

### 1.2 不要同步的内容

| 内容 | 为什么不要 |
|------|------------|
| `outputs/quickstart/`、`outputs/quickstart_cls/`、`outputs/demo_detection/` | 冒烟产物（几十条样本 1~2 轮，F1≈0），对方自己跑一次 `docs/check_all.bat` 就能重建 |
| `web/node_modules/`、`web/dist/` | 前端依赖与构建产物，`npm install` / `npm run build` 自动重建 |
| 所有 `__pycache__/`、`.pytest_cache/` | 缓存，自动重建 |
| `.idea/` `.vscode/` `.claude/settings.local.json` | IDE / 本机工具配置，**含本机绝对路径**，同步过去会让对方打开错误的目录 |
| HuggingFace 缓存（项目目录之外） | 与项目无关，别顺手打包 |

打包示例（用 7-Zip，排除上面这些；把 `<项目根>` 换成实际路径）：

```bat
cd /d <项目根>\..
7z a ScanMan_share.7z ScanMan ^
   -xr!.idea -xr!.vscode -xr!__pycache__ -xr!.pytest_cache ^
   -xr!web\node_modules -xr!web\dist ^
   -x!ScanMan\outputs\quickstart ^
   -x!ScanMan\outputs\quickstart_cls ^
   -x!ScanMan\outputs\demo_detection
```

## 3. 有哪些现成的参数可以用

`outputs/` 下每个子目录都是一次完整的训练运行，当前演示模型见 README
「模型产物与已有实验」，完整清单见 [`05_训练产物说明.md`](./05_训练产物说明.md)：

| 检查点 | 任务 | 测试集指标 | 本地有权重 | 说明 |
|--------|------|-----------|:----------:|------|
| **`merged_detection_codebert/best`** | 检测 | Precision 0.3774 / Recall 0.6779 / F1 0.4848 / ROC-AUC 0.8717（阈值 0.5） | ✅ | ⭐ 当前演示检测模型，`threshold.json` = 0.67 |
| **`merged_top27_codebert_e20/best`** | 分类（28 类） | Accuracy 0.3333 / Macro-F1 0.2392 / Top-5 0.7438 | ✅ | ⭐ 当前演示分类模型 |
| `cvefixes_detection_6ep/best` | 检测 | F1 0.7490 / ROC-AUC 0.8432 | ✅ | ⭐ CVEfixes 历史最佳 |
| `cvefixes_detection_codebert-base/best` | 检测 | F1 0.7521 / ROC-AUC 0.8396 | ❌ | ⭐ CVEfixes 第一次正式训练（**权重未随仓库分发**，指标仍在 `results.json` 里） |
| `bigvul_classification_codebert/best` | 分类 | Macro-F1 0.0822 / Top-5 0.5334 | ✅ | 单源对照 |
| `quickstart*` / `demo_detection` | 冒烟 | F1≈0 | ❌ | 只能验证流程 |

> 「本地有权重」= `best/pytorch_model.bin` 存在（约 500 MB，被 `.gitignore` 排除）。
> **运行目录里没有权重 ≠ 那次训练没发生过** —— 指标都在 `results.json` 里，
> 只是权重需要另行恢复（重新训练或从原环境拷回）。`merged_top27_codebert` 的
> `_e8` / `_e12` 变体也带权重。

每个运行目录里有什么、哪些文件能删，见 [`05_训练产物说明.md`](./05_训练产物说明.md)。

### 3.1 加载检查点还需要基础编码器（两个演示模型写法不一致）

推理**不是从 `best/` 单独跑起来的**。`VulnPredictor` 要先按 run 目录 `config.yaml` 里
`model.name` 指定的 backbone 把模型结构搭出来，才能把微调权重灌进去。而两个演示模型的写法并不一致：

| 检查点 | `config.yaml` 的 `model.name` | 实际从哪加载 |
|---|---|---|
| `merged_detection_codebert` | `microsoft/codebert-base`（HF 仓库名） | HF 缓存（`~/.cache/huggingface/`）；缓存没有就联网下载 |
| `merged_top27_codebert_e20` | `models/microsoft__codebert-base`（项目内相对路径） | 项目内的 `models/`；**该目录不存在时**，`scripts/predict.py` 的 `_resolve_backbone` 会把目录名里的 `__` 还原成 `/`，退回 HF 仓库名加载 |

两者指向的是**同一份 CodeBERT 权重**，只是写法不同，所以两种都能跑通。

> 想让整套流程**彻底离线、不碰网络**，先跑一次
> `python scripts/download_model.py --models codebert`，把 `models/microsoft__codebert-base/` 补出来
> （`models/` 被 `.gitignore` 排除，新克隆的仓库没有这份，约 477 MB）。
> 不补也能跑：检测模型走 HF 缓存，分类模型经 `_resolve_backbone` 兜底后同样走缓存，
> 只是每次加载都会向 HuggingFace 发一次请求确认版本。

**对方可以直接拿这些 `.npy` 做分析**，不用重新推理。例如扫判定阈值：

```python
import numpy as np
from sklearn.metrics import f1_score, confusion_matrix

probs = np.load(r"outputs/merged_detection_codebert/probs_test.npy")
y = np.load(r"outputs/merged_detection_codebert/labels_test.npy").astype(int)
for t in (0.5, 0.67, 0.8):
    pred = (probs >= t).astype(int)
    tn, fp, fn, tp = confusion_matrix(y, pred, labels=[0, 1]).ravel()
    print(f"阈值 {t}: F1={f1_score(y, pred):.4f}  漏报={fn}  误报={fp}")
```

## 4. ⚠️ 三个必须知道的限制

### 4.1 训练好的检查点**不能**当基座模型继续训练

想"在已有模型基础上接着训"，很自然会写：

```bat
python scripts\train.py --model outputs\merged_detection_codebert\best ...
```

**这会直接报错**（实测）：

```text
ValueError: Unrecognized model in outputs\merged_detection_codebert\best.
Should have a `model_type` key in its config.json.
```

**原因**：`best/` 里只有 `pytorch_model.bin` + 分词器 + `label_map.json`，
**没有 `config.json`**。`VulnClassifier` 的第一行就是 `AutoConfig.from_pretrained(...)`，
它需要 `config.json` 来说明"这是哪个预训练模型"。

而且 `best/pytorch_model.bin` 存的是 `VulnClassifier` 的完整 state_dict
（键名带 `encoder.` / `classifier.` 前缀），也不是 `AutoModel` 的结构。

三种可行的替代做法：

| 做法 | 命令 | 代价 | 说明 |
|------|------|------|------|
| **① 重新跑更多轮**（推荐） | `--model models/microsoft__codebert-base --epochs 6` | 前几轮重训一遍 | 见 4.2 的注意事项 |
| ② 手动续训 | 需要自己写代码 | 小 | 见 4.2 末尾的伪代码 |
| ③ 只做推理 | `predict.py --checkpoint .../best` | 无 | 这个**是可以的**，`predict.py` 会从 `config.yaml` 读回基座模型名 |

### 4.2 没有 `--resume`，"加轮数"≠"无缝续训"

`train.py` **不支持断点续训**（没有 `--resume` 参数）。想训更久只有"重新跑一遍"。

但要注意：**学习率曲线会变**，所以"6 轮训练的前 3 轮"和"3 轮训练"结果**不一样**。

```python
# scripts/train.py
steps_per_epoch = ceil(len(train_loader) / accum)
total_steps = steps_per_epoch * epochs                  # <- 轮数变了，它也跟着变
warmup_steps = int(total_steps * 0.1)                   # <- 预热步数也跟着变
```

轮数越多，预热步数越多，早期学习率越小。所以 6 轮训练是一个**全新的实验**，
不是 3 轮的延长线——对比指标时要意识到这一点。

> 如果对方想要"严格续训"，需要自己写一段加载逻辑，核心是：
>
> ```python
> model = VulnClassifier("models/microsoft__codebert-base", num_labels=2)
> model.load_state_dict(torch.load("outputs/<run>/best/pytorch_model.bin", map_location="cpu"))
> # 然后照抄 train.py 的优化器 + 训练循环，从第 N+1 轮开始跑
> ```

### 4.3 推理仍然需要预训练模型（否则会联网下载）

`predict.py` 的加载顺序是：

```text
读 best/label_map.json      -> 拿到 num_labels
读 ../config.yaml           -> 拿到 model.name（基座模型名）
VulnClassifier(model.name)  -> 先构造出完整结构（这一步要加载预训练权重）
load_state_dict(best/...)   -> 再用微调后的权重覆盖
```

**所以 `models/microsoft__codebert-base/` 是必须的**，即使你只想推理。
如果对方没同步这个目录，`AutoModel.from_pretrained("microsoft/codebert-base")` 会去
HuggingFace 下载约 477 MB。

**建议**：把要交接的运行目录里的 `config.yaml` 的 `model.name` 统一改成
`models/microsoft__codebert-base`（本地相对路径，按项目根解析），对方就完全不依赖网络了。
用 `python scripts/download_model.py --models codebert` 可以把基座模型拉到这个目录。

## 5. 对方怎么继续训练（三个典型场景）

### 场景 A：用合并数据训检测模型（README 演示口径）

```bat
cd /d <项目根>\ScanMan
set PYTHONPATH=%CD%

python scripts\train.py --task detection --source merged ^
    --model models\microsoft__codebert-base ^
    --epochs 3 --run-name merged_detection_local
```

`early_stopping_patience: 2` 会自动兜底，不必担心训过头。训完记得调阈值
（`train.py` 不写 `threshold.json`）：

```bat
python scripts\tune_threshold.py --run outputs\merged_detection_local --split val --criterion f1 --write
```

### 场景 B：换模型做对比实验

```bat
:: 换预训练模型（GraphCodeBERT 在漏洞任务上通常更强）
python scripts\download_model.py --models graphcodebert
python scripts\train.py --model models\microsoft__graphcodebert-base --run-name gcb_detection

:: 换不平衡策略
python scripts\train.py --imbalance balanced_sampler --run-name bs_detection
```

所有 `outputs/*/results.json` 可以直接横向比较。

### 场景 C：训练分类任务

```bat
python scripts\relabel_classes.py --source merged --top-k 27
python scripts\train.py --task classification --source merged_top27 ^
    --model models\microsoft__codebert-base --epochs 20 --run-name merged_top27_local
```

28 个类别（27 CWE + `OTHER`），训练完会自动生成 `report_test.txt`（逐类别 P/R/F1）。
验收看 `macro_f1` 和 `top5_accuracy`，长尾类别会明显拉低 macro。

## 6. 换目录之后必须改的地方

### 6.1 代码与脚本：0 处 ✅

`src/` 与 `scripts/` 里所有路径都从文件自身位置推出来，**换个盘符、换个目录名都能直接跑**：

```python
# src/utils.py
PROJECT_ROOT = Path(__file__).resolve().parent.parent   # 自动定位项目根
# src/config.py 中的 resolve_path() 把所有相对路径都拼到 PROJECT_ROOT 上
# docs/test_cases/test_preprocess.py
ROOT = Path(__file__).resolve().parents[2]               # 同理
```

`docs/check_all.bat` 用 `cd /d "%~dp0.."` 自动切到项目根，只在找不到 `.venv` 时才需要改解释器。

> 附带的 `findstr` 自查（只扫 `D:\Users` / `C:\Users` 这类绝对路径）覆盖不到
> `cd D:\workbuddy_workspace\vuln_bert` 这种**老项目路径**。若要做全量排查：
>
> ```bat
> findstr /s /i /n /c:"vuln_bert" /c:"workbuddy_workspace" src\*.py scripts\*.py docs\*.py docs\*.bat configs\*.*
> ```
>
> 当前 `src/` 与 `scripts/` **零命中**；`docs/` 下只在**历史记录**类文档里出现（有意保留）。

### 6.2 `outputs/<run>/config.yaml`：建议检查 1 处

如果 `config.yaml` 的 `model.name` 写的是 HuggingFace 线上名（如 `microsoft/codebert-base`），
换机器后推理/训练会走网络或 HF 缓存；改成 `models/microsoft__codebert-base` 即可完全离线。

### 6.3 `docs/check_all.bat`：0~1 处（有兜底）

脚本优先用 `<项目根>\.venv\Scripts\python.exe`，找不到就退回 PATH 上的 `python`。
对方用自己的环境时，激活后运行即可，或改脚本顶部的 `PY`。

## 7. 对方机器的环境要求

| 项目 | 要求 | 说明 |
|------|------|------|
| 操作系统 | Windows / Linux / macOS 都行 | 文档里的 `.bat` 是 Windows 的，Linux 换成对应 shell 命令 |
| Python | **3.12**（建议） | 详见 README「快速开始」 |
| PyTorch | ≥ 2.2 | 有 NVIDIA 卡就装 CUDA 版；`requirements.txt` 已配好 CUDA 13.0 额外源 |
| Node.js | 22 LTS（建议） | 只在跑 Web 前端时需要 |
| 依赖 | 见 `requirements.txt` | 它**不含 flask**，Web 后端要额外 `pip install flask` |
| 磁盘 | `data/` 约 3.1 GB + `models/` 约 0.5 GB + 每个带权重的检查点约 0.5 GB | 建议留 15 GB 余量 |
| 显存 | ≥ 6 GB 可跑 `batch_size=8 + max_length=512` | 更小就降 `--batch-size 4` 并配 `gradient_accumulation_steps` |
| 网络 | 首次可能要联网，之后可离线 | 见下方说明 |

**关于"能不能完全离线"**（这条容易想当然）：

推理/训练时要用 `config.yaml` 里的 `model.name` 去找**基座模型**。
当前 13 个检查点里，两种写法都有：

| `model.name` 写法 | 检查点 | 行为 |
|---|---|---|
| `microsoft/codebert-base`（HF repo id） | `merged_detection_codebert`、`merged_top27_codebert`、`bigvul_classification_codebert`、`cvefixes_detection_codebert-base` | 直接走 HuggingFace（或本机 HF 缓存） |
| `models/microsoft__codebert-base`（本地目录） | `merged_top27_codebert_e20`、`_e8`、`_e12`、`cvefixes_detection_6ep`、`quickstart` 等 | 目录存在就用本地；**不存在时 `_resolve_backbone()` 会打 warning 回退成 HF id** |

所以**离线的前提不是"有 `models/` 目录"，而是"本机 HF 缓存里有 codebert-base"**。
本仓库当前没有 `models/`，能正常推理是因为 HF 缓存里有。
要真正离线：把基座模型放到 `models/microsoft__codebert-base/`，
并把各 `config.yaml` 的 `model.name` 改成这个路径（或直接依赖已填充的 HF 缓存）。

### 7.1 只有 CPU 的对方怎么用

完全可以跑通，只是慢：

| 阶段 | CPU 可行性 |
|------|-----------|
| `check_env.py` / `pytest` / `test_preprocess.py` | ✅ 秒级 |
| 冒烟训练（64 条 / 1 轮 / max_length 64） | ✅ 几十秒 |
| 单段代码 / 单个文件推理 | ✅ 能用，比 GPU 慢 |
| 全量训练 | ⚠️ 能跑但很慢，建议直接用已有检查点（本仓库带权重的那些）或换到有 GPU 的机器 |
| 直接使用已有检查点 | ✅ **推荐** |
