# 项目交接与迁移指南

> **场景**：把整个项目文件夹同步给另一个人，对方拿到后能自己跑训练、继续做实验。
>
> 覆盖四件事：**同步什么 / 对方怎么验收 / 有哪些现成参数 / 换机器后会踩哪些坑**。
>
> 本文所有体积、报错、指标都来自本机实测。

---

## 0. 一句话结论

| 对方拿到什么 | 能做什么 | 不能做什么 |
|--------------|----------|------------|
| 完整文件夹（**约 6.8 GB**） | 环境自检、推理、继续训练、换数据源/换模型做对比实验、跑教学版全部脚本 | 从已训练检查点"无缝续训"（见 4.1、4.2） |
| 最小集（**约 2.9 GB**） | 上面全部，除了"改清洗规则重新构建数据集" | 同上 |

**只有一件事必须对方自己动脑**：换目录后教学版有 10 处写死的绝对路径要改（工程版 0 处）。

## 1. 同步清单

### 1.1 各部分的体积（实测）

| 内容 | 体积 | 必须同步？ | 说明 |
|------|-----:|:----------:|------|
| `vuln_bert/src/` `scripts/` `configs/` `README.md` `requirements.txt` | < 1 MB | ✅ 必须 | 全部代码。**工程版零硬编码路径**，换目录直接能用 |
| `vuln_bert/docs/` | 约 100 KB | ✅ 必须 | 本目录的 4 份文档 + 测试用例 + 一键脚本 |
| `vuln_bert/models/microsoft__codebert-base/` | **477 MB** | ✅ 强烈建议 | 带了就不用联网；**连推理都依赖它**（见 4.3） |
| `vuln_bert/data/processed/` | **1.86 GB** | ⚠️ 二选一 | 带了可直接训练，不用重新构建 |
| `vuln_bert/data/raw/` | **2.13 GB** | ⚠️ 二选一 | 带了对方才能改清洗规则重新构建数据集 |
| `vuln_bert/outputs/cvefixes_detection_codebert-base/` | **479 MB** | ✅ 建议 | **你训练好的参数**（3 轮，测试集 F1=0.7521），对方可直接推理 |
| `vuln_bert/outputs/cvefixes_detection_6ep/` | **479 MB** | ✅ 建议 | 6 轮版本（如已完成） |
| `vuln_bert_教学版/` | 约 1 MB | 可选 | 逐行中文注释的学习版 |

**三种打包方案**：

| 方案 | 内容 | 体积 | 适合 |
|------|------|-----:|------|
| **最小集** | 代码 + docs + models(477 MB) + `data/processed`(1.86 GB) + 1 个训练好的检查点(479 MB) | **约 2.9 GB** | 对方只想直接训练/推理 |
| **标准集** | 最小集 + `data/raw`(2.13 GB) | **约 5.0 GB** | 对方可能想改数据清洗规则 |
| **完整集** | 标准集 + 全部 outputs（含冒烟产物，共 2.39 GB） | **约 6.8 GB** | 原样搬一份 |

> 也就是：**当前整个文件夹实际占 6.8 GB**，其中 **1.4 GB 是可以不带的冒烟产物**（见 1.2）。

> 说明：`data/raw`（2.13 GB）和 `data/processed`（1.86 GB）**不必都带**。
> 只带 `processed` → 对方能立刻训练，但不能改清洗逻辑。
> 只带 `raw` → 对方要先跑 `build_dataset.py`（约 3 分钟）才能训练，但能改清洗逻辑。

## 3. 有哪些现成的参数可以用

`outputs/` 下每个子目录都是一次完整的训练运行：

| 检查点 | 任务 | 数据量 | 测试集指标 | 能不能用 |
|--------|------|-------:|------------|----------|
| **`cvefixes_detection_codebert-base/best`** | 检测 | 15,147 条 / 3 轮 | **F1 = 0.7521**，acc 0.7618，ROC-AUC 0.8396 | ⭐ **可用** |
| `cvefixes_detection_6ep/best` | 检测 | 15,147 条 / 6 轮 | 训练中 | ⭐ 预计更好 |
| `quickstart/best` | 检测 | 64 条 / 1 轮 | F1 = 0.00 | ❌ 只能验证流程 |
| `quickstart_cls/best` | 分类（41 类） | 64 条 / 1 轮 | macro-F1 = 0.02 | ❌ 只能验证流程 |
| `demo_detection/best` | 检测 | 64 条 / 2 轮 | F1 = 0.00 | ❌ 只能验证流程 |

每个运行目录里有什么：

```
outputs/<run_name>/
├── config.yaml              ← 这次训练用的完整配置（可复现）
├── results.json             ← 每轮指标 + 测试集指标
├── report_val/test.txt      ← 逐类别 P/R/F1（只有分类任务有）
├── logits_*.npy  labels_*.npy  probs_*.npy   ← 原始输出，可画 ROC/PR、扫阈值
└── best/
    ├── pytorch_model.bin    ← 模型权重（约 475 MB）
    ├── tokenizer.json       ← 分词器
    ├── tokenizer_config.json
    └── label_map.json       ← 任务类型 + 类别数 + id2name
```

**对方可以直接拿这些 `.npy` 做分析**，不用重新推理。例如扫判定阈值：

```python
import numpy as np
from sklearn.metrics import f1_score, confusion_matrix

probs = np.load(r"outputs\cvefixes_detection_codebert-base\probs_test.npy")
y = np.load(r"outputs\cvefixes_detection_codebert-base\labels_test.npy").astype(int)
for t in (0.3, 0.4, 0.5):
    pred = (probs >= t).astype(int)
    tn, fp, fn, tp = confusion_matrix(y, pred, labels=[0, 1]).ravel()
    print(f"阈值 {t}: F1={f1_score(y, pred):.4f}  漏报={fn}  误报={fp}")
```

## 4. ⚠️ 三个必须知道的限制

### 4.1 训练好的检查点**不能**当基座模型继续训练

想"在已有模型基础上接着训"，很自然会写：

```bat
python scripts\train.py --model outputs\cvefixes_detection_codebert-base\best ...
```

**这会直接报错**（实测）：

```
ValueError: Unrecognized model in outputs\cvefixes_detection_codebert-base\best.
Should have a `model_type` key in its config.json.
```

**原因**：`best/` 里只有 `pytorch_model.bin` + 分词器 + `label_map.json`，
**没有 `config.json`**。`VulnClassifier` 的第一行就是 `AutoConfig.from_pretrained(...)`，
它需要 `config.json` 来说明"这是哪个预训练模型"，而检查点里没有。

而且 `best/pytorch_model.bin` 存的是 `VulnClassifier` 的完整 state_dict
（键名带 `encoder.` / `classifier.` 前缀），也不是 `AutoModel` 的结构。

三种可行的替代做法：

| 做法 | 命令 | 代价 | 说明 |
|------|------|------|------|
| **① 重新跑更多轮**（推荐） | `--model models\microsoft__codebert-base --epochs 6` | 前几轮重训一遍 | 见 4.2 的注意事项 |
| ② 手动续训 | 需要自己写代码 | 小 | 见 4.2 末尾的伪代码 |
| ③ 只做推理 | `predict.py --checkpoint .../best` | 无 | 这个**是可以的**，因为 `predict.py` 会从 `config.yaml` 里读回基座模型名 |

### 4.2 没有 `--resume`，"加轮数"≠"无缝续训"

`train.py` **不支持断点续训**（没有 `--resume` 参数）。想训更久只有"重新跑一遍"。

但要注意：**学习率曲线会变**，所以"6 轮训练的前 3 轮"和"3 轮训练"结果**不一样**。

```python
# src/train.py
steps_per_epoch = ceil(len(train_loader) / accum)      # 15147/16 = 947
total_steps = steps_per_epoch * epochs                  # <- 轮数变了，它也跟着变
optimizer, scheduler = build_optimizer_scheduler(model, cfg, total_steps)
warmup_steps = int(total_steps * 0.1)                   # <- 预热步数也跟着变
```

| | `epochs=3` | `epochs=6` |
|---|---:|---:|
| 总步数 | 2,841 | 5,682 |
| 预热步数（10%） | **284** | **568** |
| 第 50 步的学习率 | 3.52e-06 | 1.76e-06（**只有一半**） |
| 达到峰值学习率的位置 | 第 284 步（epoch 1 内） | 第 568 步（epoch 1 末） |

上面 `epochs=3` 那一列是从实测日志里核对过的（日志里 `step 50 | lr 3.52e-06`）。
所以 6 轮训练是一个**全新的实验**，不是 3 轮的延长线——对比指标时要意识到这一点。

> 如果对方想要"严格续训"，需要自己写一段加载逻辑，核心是：
>
> ```python
> model = VulnClassifier("models/microsoft__codebert-base", num_labels=2)
> model.load_state_dict(torch.load("outputs/<run>/best/pytorch_model.bin", map_location="cpu"))
> # 然后照抄 train.py 的优化器 + 训练循环，从第 N+1 轮开始跑
> ```

### 4.3 推理仍然需要预训练模型（否则会联网下载）

`predict.py` 的加载顺序是：

```
读 best/label_map.json      -> 拿到 num_labels
读 ../config.yaml           -> 拿到 model.name（基座模型名）
VulnClassifier(model.name)  -> 先构造出完整结构（这一步要加载预训练权重）
load_state_dict(best/...)   -> 再用微调后的权重覆盖
```

**所以 `models/microsoft__codebert-base/` 是必须的**，即使你只想推理。
如果对方没同步这个目录，`AutoModel.from_pretrained("microsoft/codebert-base")` 会去
HuggingFace 下载 477 MB。

**还有一个坑**：`config.yaml` 里记的基座模型名不同，行为也不同：

| 运行 | `config.yaml` 里的 `model.name` | 换机器后的行为 |
|------|-------------------------------|----------------|
| `cvefixes_detection_codebert-base` | `microsoft/codebert-base`（线上名） | 走 HF 缓存 / 联网下载 |
| `cvefixes_detection_6ep` | `models\microsoft__codebert-base`（相对路径） | 直接读本地目录 ✅ |

**建议**：把要交接的运行目录里的 `config.yaml` 手动改成
`name: models/microsoft__codebert-base`，对方就完全不依赖网络了。

## 5. 对方怎么继续训练（三个典型场景）

### 场景 A：训得更久（最常用）

```bat
cd /d <项目根>\vuln_bert
set PYTHONPATH=%CD%

python scripts\train.py --task detection --source cvefixes ^
    --model models\microsoft__codebert-base ^
    --epochs 6 --run-name cvefixes_detection_6ep
```

预计 RTX 3060 Laptop 上约 55 分钟（实测每轮 8~10 分钟）。
`early_stopping_patience: 2` 会自动兜底，不必担心训过头。

### 场景 B：换模型做对比实验

```bat
:: 换预训练模型（GraphCodeBERT 在漏洞任务上通常更强）；数据源固定为 cvefixes
python scripts\download_model.py --models graphcodebert
python scripts\train.py --model models\microsoft__graphcodebert-base --run-name gcb_detection

:: 换不平衡策略
python scripts\train.py --imbalance balanced_sampler --run-name bs_detection
```

所有 `outputs/*/results.json` 可以直接横向比较。

### 场景 C：训练分类任务

```bat
python scripts\train.py --task classification --source cvefixes ^
    --model models\microsoft__codebert-base --run-name cvefixes_cls_6ep
```

41 个 CWE 类别，训练完会自动生成 `report_test.txt`（逐类别 P/R/F1）。
验收看 `macro_f1` 和 `weighted_f1`，长尾类别会明显拉低 macro。

> 教学版的分类模块 `_03_bert分类/model/` 是空的，
> 对方要先训一次 `_03_bert分类/_05_bert模型训练代码_gpu.py` 才能跑它的网页版。

## 7. 对方机器的环境要求

| 项目 | 要求 | 说明 |
|------|------|------|
| 操作系统 | Windows / Linux / macOS 都行 | 文档里的 `.bat` 是 Windows 的，Linux 换成对应 shell 命令 |
| Python | **3.9 ~ 3.13** | 本项目在 3.12.13（conda）和 3.13.14（venv）上都验证通过 |
| PyTorch | ≥ 2.2 | 有 NVIDIA 卡就装 CUDA 版，本机用的是 `cu130` |

| 显存 | ≥ 6 GB 可跑 `batch_size=8 + max_length=512`（本机 6 GB 实测不 OOM） | 更小就降 `--batch-size 4` 并配 `gradient_accumulation_steps` |
| 网络 | **可以完全离线** | 前提是同步了 `models/` 且把 `config.yaml` 的 `model.name` 指到本地路径 |

### 7.1 只有 CPU 的对方怎么用

完全可以跑通，只是慢：

| 阶段 | CPU 可行性 |
|------|-----------|
| `check_env.py` / `test_preprocess.py` | ✅ 秒级 |
| 冒烟训练（64 条 / 1 轮 / max_length 64） | ✅ 约 15 秒（实测 5.7 samples/s） |

| 全量训练（15,147 条 × 3 轮） | ⚠️ 约 2.2 小时（5.7 samples/s），能跑但慢 |
| 直接使用已有的检查点 | ✅ **推荐**——不用训练就有 F1=0.7521 的模型 |
