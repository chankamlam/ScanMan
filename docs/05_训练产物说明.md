# 训练产物说明（`outputs/`）

> 本文件说明 `../outputs/` 里每个目录、每个文件是什么、怎么用、能不能删。
>
> 每次训练（`python scripts/train.py --run-name XXX`）会在 `outputs/` 下建一个
> 以 `XXX` 命名的子目录，一次实验一个目录，互不干扰。

---

## 1. 单个运行目录的结构

以 `outputs/cvefixes_detection_6ep/` 为例：

```
outputs/cvefixes_detection_6ep/
├── config.yaml                本次训练实际生效的完整配置（含命令行覆盖项）
├── results.json               每轮指标 + 最终 val/test 指标
├── report_val.txt             逐类别 P/R/F1 明细（**只有分类任务有**）
├── report_test.txt            同上，测试集
├── logits_val.npy             原始 logits（可以自己算任何指标）
├── logits_test.npy
├── labels_val.npy             真实标签
├── labels_test.npy
├── probs_val.npy              "有漏洞"的概率（**只有检测任务有**）
├── probs_test.npy
└── best/                      验证集最优的那一轮权重
    ├── pytorch_model.bin      模型权重，约 475 MB
    ├── tokenizer.json         分词器（保证推理时切词方式与训练一致）
    ├── tokenizer_config.json
    ├── label_map.json         任务类型 + 类别数 + 编号↔名称
    └── threshold.json         判定阈值（**可选**，由 tune_threshold.py 生成）
```

| 文件 | 用途 | 能不能删 |
|------|------|----------|
| `config.yaml` | 复现实验的唯一依据。`predict.py` 也靠它还原模型结构 | ❌ 不能删 |
| `results.json` | 训练日志的机器可读版，做对比实验时直接读它 | ❌ 建议留 |
| `best/` | **推理必需**（`predict.py --checkpoint <这个目录>`） | ❌ 不能删 |
| `best/threshold.json` | 调优后的判定阈值，`predict.py` 会自动读取 | ❌ 建议留 |
| `probs_*.npy` / `logits_*.npy` / `labels_*.npy` | 事后分析用（扫阈值、画 ROC/PR 曲线） | ⚠️ 小文件（<20 KB），留着方便 |
| `report_*.txt` | 分类任务的逐类别明细 | ⚠️ 小文件，留着方便 |

> **每个检查点约 475 MB**，跑很多组对比实验时注意磁盘。
> `configs/config.yaml` 里的 `save_total_limit` 控制保留几个中间检查点。

## 2. 当前有哪些运行

| 目录 | 任务 | 数据量 | 测试集 F1 | 召回率 | 说明 |
|------|------|-------:|----------:|-------:|------|
| **`cvefixes_detection_6ep`** ⭐ | 检测 | 15,147 × 6 轮 | **0.7495** | **0.9402**（阈值 0.11） | **当前最好的模型，默认用它** |
| `cvefixes_detection_codebert-base` | 检测 | 15,147 × 3 轮 | 0.7521 | 0.9004（阈值 0.255） | 第一次正式训练 |
| `data50_6ep` | 检测 | **7,573** × 6 轮 | 0.7211 | — | 学习曲线：一半数据，第 2 轮早停 |
| `data25_6ep` | 检测 | **3,787** × 6 轮 | 0.7185 | — | 学习曲线：四分之一数据，第 4 轮早停 |
| `quickstart` | 检测 | 64 × 1 轮 | 0.00 | — | 冒烟验证，**没有检测能力** |
| `quickstart_cls` | 分类 | 64 × 1 轮 | macro-F1 0.02 | — | 冒烟验证，**没有分类能力** |
| `demo_detection` | 检测 | 64 × 2 轮 | 0.00 | — | 项目最早期自带的冒烟产物 |

> **`data25_6ep` / `data50_6ep` 是"样本量够不够"这个问题的实验证据**，
> 详见 [`01_数据集与模型全解析.md`](./01_数据集与模型全解析.md) 第 5.11 节。
> 三个规模（3.8k / 7.6k / 15.1k）的 F1 是 0.7185 / 0.7211 / **0.7490**，
> ROC-AUC 是 0.783 / 0.796 / **0.843**——单调上升，说明**数据还在起作用，没饱和**。
> 这两个实验目录可以不长期保留（重跑一次约 15 / 25 分钟）。

> 6 轮和 3 轮的 F1 几乎一样（0.7495 vs 0.7521），但**在低阈值下 6 轮更好**：
> 同样要求 90% 召回率，3 轮只能到 precision 0.649，6 轮能到 0.661。
> 也就是说多训的 3 轮主要改善的是"排序质量"，在默认阈值 0.5 下看不出来。
>
> 而且 6 轮训练**从第 4 轮开始过拟合**（val F1：0.732 → 0.715 → 0.719，
> 但 train_loss 一路降到 0.25）。所以 6 轮已经到顶，再加轮数没有收益。

## 3. 怎么用这些产物

### 3.1 做推理

```bat
python scripts\predict.py --checkpoint outputs\cvefixes_detection_6ep\best --file demo.c
```

### 3.2 在完整测试集上评估

```bat
python scripts\evaluate.py ^
    --checkpoint outputs\cvefixes_detection_6ep\best ^
    --input data\processed\cvefixes_detection_test.jsonl --sweep
```

### 3.3 重新调判定阈值

```bat
python scripts\tune_threshold.py --run outputs\cvefixes_detection_6ep ^
    --target-recall 0.90 --write
```

它会读 `probs_val.npy` 在**验证集**上找阈值（不在测试集上找，避免偷看答案），
然后写进 `best/threshold.json`。

### 3.4 自己做分析

```python
import numpy as np
from sklearn.metrics import f1_score, confusion_matrix

probs = np.load(r"outputs\cvefixes_detection_6ep\probs_test.npy")
y = np.load(r"outputs\cvefixes_detection_6ep\labels_test.npy").astype(int)

for t in (0.5, 0.3, 0.2, 0.11):
    pred = (probs >= t).astype(int)
    tn, fp, fn, tp = confusion_matrix(y, pred, labels=[0, 1]).ravel()
    print(f"阈值 {t}: F1={f1_score(y, pred):.4f} 漏报={fn} 误报={fp}")
```

### 3.5 横向对比多组实验

```python
import json
from pathlib import Path

for p in sorted(Path("outputs").glob("*/results.json")):
    r = json.loads(p.read_text(encoding="utf-8"))
    t = r.get("test", {})
    key = "f1" if r["task"] == "detection" else "macro_f1"
    print(f"{p.parent.name:<40} {key}={t.get(key, float('nan')):.4f}")
```

## 4. 清理建议

三个冒烟产物（`quickstart` / `quickstart_cls` / `demo_detection`）各约 475 MB，
合计 **1.4 GB**，都**没有实际能力**（F1≈0），只是用来验证流水线。
它们的唯一价值是让你不用重新训练就能跑一遍 `predict.py`。

不需要了可以直接删：

```bat
cd /d <项目根>\vuln_bert\outputs
rd /s /q quickstart
rd /s /q quickstart_cls
rd /s /q demo_detection
```

删掉之后 `docs/check_all.bat` 会自动重新生成 `quickstart`。

> ⚠️ **不要删 `cvefixes_detection_6ep` 和 `cvefixes_detection_codebert-base`**，
> 这两个是真正训练出来的模型，重训一次要 30~55 分钟。
