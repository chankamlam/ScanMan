# 训练产物说明（`outputs/`）

> 本文件说明 `../outputs/` 里每个目录、每个文件是什么、怎么用、能不能删。
>
> 每次训练（`python scripts/train.py --run-name XXX`）会在 `outputs/` 下建一个
> 以 `XXX` 命名的子目录，一次实验一个目录，互不干扰。

---

## 1. 单个运行目录的结构

以 `outputs/merged_detection_codebert/`（**检测**任务）为例：

> 📌 这是**检测**任务，所以**没有** `report_val.txt` / `report_test.txt` ——
> 那两个是分类任务才有的逐类别明细。下面把两种任务各自会出现的文件都列了出来。

```text
outputs/merged_detection_codebert/
├── config.yaml                本次训练实际生效的完整配置（含命令行覆盖项）
├── results.json               每轮指标 + 最终 val/test 指标
├── report_val.txt             逐类别 P/R/F1 明细（**只有分类任务有**，本目录没有）
├── report_test.txt            同上，测试集（本目录没有）
├── logits_val.npy             原始 logits（可以自己算任何指标）
├── logits_test.npy
├── labels_val.npy             真实标签
├── labels_test.npy
├── probs_val.npy              "有漏洞"的概率（**只有检测任务有**）
├── probs_test.npy
└── best/                      验证集最优的那一轮权重
    ├── pytorch_model.bin      模型权重，约 475 MB（不纳入 Git）
    ├── tokenizer.json         分词器（不纳入 Git，可用 download_model.py 重新拉）
    ├── tokenizer_config.json
    ├── label_map.json         任务类型 + 类别数 + 编号↔名称
    └── threshold.json         判定阈值（**可选**，由 tune_threshold.py 生成）
```

| 文件 | 用途 | 能不能删 |
|------|------|----------|
| `config.yaml` | 复现实验的唯一依据。`predict.py` 也靠它还原模型结构 | ❌ 不能删 |
| `results.json` | 训练日志的机器可读版，做对比实验时直接读它 | ❌ 建议留 |
| `best/` | **推理必需**（`predict.py --checkpoint <这个目录>`） | ❌ 不能删 |
| `best/threshold.json` | 调优后的判定阈值，`predict.py` 会自动读取 | ❌ 建议留 |
| `probs_*.npy` / `logits_*.npy` / `labels_*.npy` | 事后分析用（扫阈值、画 ROC/PR 曲线） | ⚠️ 小文件，留着方便（不纳入 Git） |
| `report_*.txt` | 分类任务的逐类别明细 | ⚠️ 小文件，留着方便 |

> **每个带权重的检查点约 475 MB**，跑很多组对比实验时注意磁盘。
>
> ⚠️ `configs/config.yaml` 里的 **`save_total_limit` 目前不起作用** ——
> `train.py` 不读这个键，也不会产生 `checkpoint-*` 中间目录，
> 全程只保存验证集最优的那一份 `best/`。该配置项在 `src/config.py` 里有默认值但无人使用。
>
> Git 只保留 `config.yaml` / `results.json` / `report_*.txt` / `label_map.json` 等小文件，
> 权重、分词器和 `.npy` 都被 `.gitignore` 排除。**所以 clone 下来的运行目录大多没有权重**，
> 指标在 `results.json` 里仍然可读。

## 3. 怎么用这些产物

### 3.1 做推理

```bash
python scripts/predict.py --checkpoint outputs/merged_detection_codebert/best --file demo.c
```

### 3.2 在完整测试集上评估

```bash
python scripts/evaluate.py --checkpoint outputs/merged_detection_codebert/best --input data/processed/merged_detection_test.jsonl --sweep
```

### 3.3 重新调判定阈值

```bash
python scripts/tune_threshold.py --run outputs/merged_detection_codebert --split val --criterion f1 --write
```

它会读 `probs_val.npy` 在**验证集**上找阈值（不在测试集上找，避免偷看答案），
然后写进 `best/threshold.json`。也可用 `--criterion recall --target-recall 0.90`
按目标召回率选阈值。

### 3.4 自己做分析

```python
import numpy as np
from sklearn.metrics import f1_score, confusion_matrix

probs = np.load(r"outputs/merged_detection_codebert/probs_test.npy")
y = np.load(r"outputs/merged_detection_codebert/labels_test.npy").astype(int)

for t in (0.5, 0.67, 0.8):
    pred = (probs >= t).astype(int)
    tn, fp, fn, tp = confusion_matrix(y, pred, labels=[0, 1]).ravel()
    print(f"阈值 {t}: F1={f1_score(y, pred):.4f} 漏报={fn} 误报={fp}")
```

### 3.5 横向对比多组实验

```python
import json
from pathlib import Path

for p in sorted(Path("outputs").glob("*/results.json")):
    r = json.loads(p.read_text(encoding="utf-8"))
    t = r.get("test", {})
    key = "f1" if r["task"] == "detection" else "macro_f1"
    print(f"{p.parent.name:<40} {key}={t.get(key, float('nan')):.4f}")
```

## 4. 清理建议

三个冒烟产物（`quickstart` / `quickstart_cls` / `demo_detection`）只是用来验证流水线，
没有实际能力，它们的唯一价值是让你不用重新训练就能跑一遍 `predict.py`。
不需要了可以直接删（注意别删错目录）：

```bat
cd /d <项目根>\ScanMan\outputs
rd /s /q quickstart
rd /s /q quickstart_cls
rd /s /q demo_detection
```

删掉之后 `docs/check_all.bat` 会自动重新生成 `quickstart`
（前提是先备好 `models/` 与 `data/processed/`，见 `docs/README.md`）。

## 5. `outputs/` 顶层的零散文件

除了「一次实验一个目录」，`outputs/` 顶层还有一批**单文件产物**，
大多是历史扫描/实验的留档。它们不属于任何一次训练：

| 文件 | 是什么 | 能删吗 |
|---|---|---|
| `demo_verified_report.json`、`scan_demo_verified.json` | 用当前两个演示检查点扫 `demo_verified/` 的产物（两份内容相同，都是 13 文件 / 30 函数 / 23 可疑、阈值 0.67） | ⚠️ 留档，可重新生成 |
| `scan_result.json`、`scan_src_inference.json` | 早期扫本仓库 `src/` 的产物（`docs/06` §3.6、`docs/07` §6.5 引用的「47 个函数」就出自这里） | ⚠️ 留档 |
| `spike_align.json` | `spike_align.py` 的分布对比实验产物（`docs/07` §6.2/6.3 引用） | ⚠️ 留档 |
| `_demo_pool.json` | 早期演示素材池 | 可删 |
| `classify_train.log` | 早期分类训练的日志 | 可删 |
| `demo_real_report.json`、`scan_demo_real.json`、`scan_demo_synthetic.json`、`scan_repo.json` | **历史产物，`root` 指向已删除的 `demo_real/`、`demo_synthetic/`** | ❌ 建议删（路径已失效） |

> ⚠️ 上表中 `demo_real_report.json` / `scan_demo_real.json` / `scan_demo_synthetic.json` /
> `scan_repo.json` 这 4 个引用的是**已经不存在的目录**，留着只会误导。
> 它们没有纳入 Git（`.gitignore` 排除 `outputs/` 下的大部分产物），删掉不影响仓库。

> ⚠️ **`merged_detection_codebert` / `merged_top27_codebert_e20` 是当前演示模型，
> 不要删。** 仓库不提交权重，删了就要重新训练或从备份恢复。
