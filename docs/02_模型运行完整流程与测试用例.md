## 0. 五分钟跑通（TL;DR）

如果你只想**确认整条流水线能跑**，按顺序执行下面 4 条命令即可（CPU 版，合计约 40 秒）：

```bat
cd /d <项目根>\ScanMan
set PYTHONPATH=%CD%

:: 先用 README「快速开始」路径二第 1 步建好 .venv 并激活；激活后直接用 python 即可
:: 也可以把 PY 指向任意解释器：set PY=D:\path\to\python.exe
set PY=python

%PY% scripts\check_env.py                                          :: ① 环境自检
%PY% -m pytest tests\ -q                                           :: ② 单元测试
%PY% docs\test_cases\test_preprocess.py                            :: ③ 预处理断言
%PY% scripts\train.py --model models\microsoft__codebert-base ^
      --epochs 1 --max-train-samples 64 ^
      --max-eval-samples 32 --batch-size 8 --max-length 64 ^
      --run-name quickstart                                       :: ④ 冒烟训练（CPU 约 15 s，GPU 约 5 s）
%PY% scripts\predict.py --checkpoint outputs\quickstart\best ^
      --input docs\test_cases\detection_test_cases.jsonl ^
      --output docs\test_cases\out_detection.jsonl                 :: ⑤ 批量推理
```

> 想去掉 GPU 依赖时给训练/推理命令加 `--cpu` / `--device cpu`。

各步骤耗时与预期结果：

| 步骤 | 耗时 | 预期结果 |
|------|-----:|----------|
| ① 环境自检 | 5 s | 依赖无 `[FAIL]`；有 GPU 时打印型号与显存 |
| ② 单元测试 | < 1 min | `pytest` 全部通过 |
| ③ 预处理断言 | < 1 s | `全部通过` |
| ④ 冒烟训练 | CPU 15 s / GPU 5 s | `训练完成 ✅`，生成 `outputs/quickstart/best/` |
| ⑤ 批量推理 | 7 s | 生成 `docs/test_cases/out_detection.jsonl` |

> ⚠️ **冒烟模型的预测结果全部是垃圾**（准确率 40%，接近瞎猜）。它的唯一作用是证明
> "数据能读、模型能建、能训练、能保存、能加载、能推理"。要看真实效果必须做第 6 步的正式训练。

## 1. 环境准备

### 1.1 推荐环境

按 README「快速开始」路径二第 1 步创建独立虚拟环境（建议 Python 3.12）：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m pip install flask
python scripts/check_env.py
```

`check_env.py` 会报告 Python 版本、依赖、GPU 型号与显存、原始数据、处理后数据、
本地模型是否就绪。**不要在文档里写死解释器绝对路径**：谁的环境谁自己激活。

### 1.2 训练速度参考（历史实测，CVEfixes 检测任务）

| 设备 | max_length | batch_size | 吞吐 | 单 epoch 估算（15,147 条） |
|------|-----------:|-----------:|-----:|---------------------------:|
| CPU | 64 | 8 | 5.7 samples/s | ~44 分钟 |
| **RTX 3060 Laptop 6 GB** | 256 | 8 | **43.2 samples/s** | ~6 分钟 |
| **RTX 3060 Laptop 6 GB** | 512 | 8 | **18.8 samples/s** | ~13 分钟 |

> 6 GB 显存实测可以跑 `batch_size=8 + max_length=512`，**不会 OOM**。换机器后以实测为准。

### 1.3 GPU 用户额外一步

> ✅ 如果你用的是 README 的推荐环境且已装 CUDA 版 PyTorch，这一步可以跳过。
> 下面只在你换机器 / 重建环境时才需要。

```powershell
# 先看驱动支持的 CUDA 版本
nvidia-smi
# 再装对应版本的 PyTorch（cu130 / cu128 / cu126 按需替换）
pip install torch --index-url https://download.pytorch.org/whl/cu130
```

装好后 `check_env.py` 会打印 GPU 型号与显存，`train.py` 会自动选 CUDA、自动开混合精度。

### 1.4 三条命令约定

1. **所有命令都在 ScanMan 项目根目录执行**，
   否则 `configs/config.yaml` 这类相对路径会找不到。
2. **`PYTHONPATH` 指向项目根**（`set PYTHONPATH=%CD%`）最保险：`scripts/*.py` 里有
   `from src.config import ...`；脚本自身也做了 `sys.path` 兜底。
3. **中文输出乱码时**先执行 `chcp 65001`，再 `set PYTHONIOENCODING=utf-8`。

### 步骤 6 —— 正式训练（需要 GPU）

```bat
:: 任务 A：漏洞检测（二分类）
python scripts\train.py --task detection --source cvefixes --model models\microsoft__codebert-base

:: 任务 A'：合并数据检测（README 演示口径）
python scripts\train.py --task detection --source merged --model models\microsoft__codebert-base --run-name merged_detection_local

:: 任务 B：漏洞分类（CVEfixes：40 CWE + OTHER = 41 类）
python scripts\train.py --task classification --source cvefixes --model models\microsoft__codebert-base

:: 任务 B'：28 类分类（README 演示口径，先重标标签）
python scripts\relabel_classes.py --source merged --top-k 27
python scripts\train.py --task classification --source merged_top27 --model models\microsoft__codebert-base --epochs 20 --run-name merged_top27_local
```

> ⚠️ **务必用本地路径 `models\microsoft__codebert-base`，不要写 `microsoft/codebert-base`。**
> 后者是 HuggingFace 仓库名，会触发一次约 1 GB 的重复下载
> （`pytorch_model.bin` 473 MB + `model.safetensors` 499 MB），而你本地已经有同一份权重。
> 而且这个名字会被记进 `outputs/<run>/config.yaml`，以后 `predict.py` 也会去读线上缓存。

默认配置（`configs/config.yaml`）：`epochs=3`、`batch_size=16`、`lr=2e-5`、`head_lr=1e-4`、
`max_length=512`、`warmup_ratio=0.1`、`early_stopping_patience=2`。

**耗时参考**（本机实测 + 估算）：

| 设备 | 配置 | 吞吐 | CVEfixes 检测 1 epoch |
|------|------|-----:|----------------------|
| **RTX 3060 Laptop 6 GB** | `batch 8 / max_length 512` | 18.8 samples/s | **约 13 分钟** |
| **RTX 3060 Laptop 6 GB** | `batch 8 / max_length 256` | 43.2 samples/s | 约 6 分钟 |
| 隔离 venv（CPU） | `batch 8 / max_length 64` | 5.7 samples/s | 约 44 分钟 |
| RTX 3090（历史记录，非本机实测） | 默认 | — | 约 15 分钟 |

> 建议直接用默认配置（`batch_size=16` 先试，OOM 再降到 8）。
> 本机 6 GB 显存实测 `batch_size=8 + max_length=512` **不会 OOM**。

> 📌 **想训得更久（接着 3 轮继续）看 [`03_项目交接与迁移指南.md`](./03_项目交接与迁移指南.md) 第 4.1、4.2 节。**
> 关键结论：训练好的 `best/` **不能**当基座模型继续训练（里面没有 `config.json`，实测报
> `ValueError: Unrecognized model`），只能重新跑 `--epochs 6`；
> 而且预热步数会随总步数一起变（284 → 568），所以 6 轮不是 3 轮的延长线。

**显存不够时**：

```bat
:: 方案一：降 batch + 梯度累积（等效 batch 仍是 16）
python scripts\train.py --batch-size 4 --max-length 256
:: 然后到 configs/config.yaml 里把 gradient_accumulation_steps 改成 4

:: 方案二：直接降序列长度
python scripts\train.py --batch-size 8 --max-length 256
```

**常用覆盖参数**：

| 参数 | 说明 |
|------|------|
| `--model` | 预训练模型名或本地路径 |
| `--epochs` / `--batch-size` / `--lr` | 轮数 / 批大小 / 学习率 |
| `--max-length` | 512 / 256 / 128 |
| `--max-train-samples` | 限制训练样本数（调试） |
| `--imbalance` | `weighted_loss`（默认）/ `balanced_sampler` / `none` |
| `--run-name` | 输出子目录名 |
| `--cpu` | 强制 CPU |

**通过标准**：`outputs/<run_name>/results.json` 里 test 的 F1（检测）或 macro_f1（分类）达到第 4.7 节的预期区间。
分类任务还会额外生成 `report_test.txt`（逐类别 P/R/F1）。

### 步骤 8 —— Web 上传扫描

ScanMan 的 Web 是「React 前端 + Flask 后端」：

```bat

npm run dev
```

浏览器打开 <http://localhost:5173>，等待页眉显示模型就绪，添加源文件后点「开始检测」。

**前提**：检测检查点（默认 `outputs/merged_detection_codebert/best`）和分类检查点
（默认 `outputs/merged_top27_codebert_e20/best`）都存在且权重完整。模型未就绪时
`/api/health` 返回 `loading`，扫描请求返回 503；参数错误返回 400；已有扫描在进行返回 409。

**不想开浏览器也能验证接口**（后端已启动的前提下）：

```bat
curl http://127.0.0.1:8000/api/health
```

## 4. 测试用例

### 4.1 设计原则

| 层次 | 测什么 | 文件 | 是否需要 GPU |
|------|--------|------|--------------|
| **单元级** | 清洗 / 截断 / CWE 规范化 / 分组划分 / 标签映射 | `test_cases/test_preprocess.py` | 否 |
| **端到端·检测** | 一段源码 → `safe` / `vulnerable` | `test_cases/detection_test_cases.jsonl` | 否 |
| **端到端·分类** | 一段漏洞代码 → CWE 类型 | `test_cases/classification_test_cases.jsonl` | 否 |

用例的选取遵循三条：

1. **覆盖高频 CWE**。CVEfixes 里样本最多的几类是 CWE-79（XSS）、CWE-125（越界读）、
   CWE-89（SQL 注入）、CWE-20（输入校验）、CWE-787/CWE-120（越界写）——用例优先覆盖它们。
2. **正负成对**。每个漏洞用例都配一条"修好之后"的安全用例（如 `det01` 溢出 vs `det07` 加了长度限制），
   这是最难的判别场景，也是这套数据的设计初衷。
3. **跨语言**。覆盖 C、PHP、Python，检验模型不是只记住了 C 的语法。

**断言明细**（挑几个关键的）：

| 断言 | 期望 | 为什么重要 |
|------|------|-----------|
| `_clean_code("a\r\nb") == "a\nb"` | 换行统一 | 不统一则 MD5 去重跨平台失效 |
| `_clean_code("// 注释\nx=1")` 保留注释 | 只 strip 不动内容 | 证明"清洗"没做过度处理 |
| `_norm_cwe("CWE-079") == "CWE-79"` | 去前导零 | 不去零会把同一 CWE 拆成两个类 |
| `_norm_cwe("NVD-CWE-noinfo") == ""` | 无效值置空 | 否则会多出一个假类别 |
| `truncate_code("a"*100, 10, 0.6)` | `aaaaaa…（注释）…aaaa` | 头尾比例必须精确（6:4） |
| `split_groups(...)` 三集合组无重叠 | 交集为空 | **防数据泄漏的核心断言** |
| `{2} == 每组的样本数` | 每对 vuln/fixed 未被拆开 | 拆开 = 测试集出现训练集的近邻副本 |
| 同 seed 两次划分结果相同 | 可复现 | 保证实验对比有意义 |

### 4.6 实测结果

> ⚠️ 下面 A/B 两组是本文件写作时的历史实测，当时用例集只有 **10 条**；
> 现在 `detection_test_cases.jsonl` 已扩到 **20 条**，复跑得到的数字会不同。

#### A. 正式训练后的模型（`outputs/cvefixes_detection_codebert-base/best`，测试集 F1=0.7521）

```
python scripts\predict.py --checkpoint outputs\cvefixes_detection_codebert-base\best ^
    --input docs\test_cases\detection_test_cases.jsonl ^
    --output docs\test_cases\out_detection_real.jsonl --batch-size 4

→ 与 gold 标签对比准确率: 0.6000 (6/10)
```

逐条明细：

| 用例 | 期望 | 预测 | P(漏洞) | 结果 |
|------|-----:|------|--------:|:----:|
| det03 XSS | 1 | vulnerable | 0.9572 | ✅ |
| det05 路径遍历 | 1 | vulnerable | 0.8127 | ✅ |
| det02 SQL 注入 | 1 | vulnerable | 0.8011 | ✅ |
| det06 空指针解引用 | 1 | safe | 0.4712 | ❌ |
| det01 栈溢出 | 1 | safe | 0.3928 | ❌ |
| det04 命令注入 | 1 | safe | 0.1333 | ❌ |
| det08 参数化查询 | 0 | vulnerable | 0.7668 | ❌（误报） |
| det07 安全的 strncpy | 0 | safe | 0.2920 | ✅ |
| det09 HTML 转义 | 0 | safe | 0.0725 | ✅ |
| det10 边界检查 | 0 | safe | 0.0104 | ✅ |

**怎么解读这 6/10**：

- 这 10 条是 **2~3 行的短片段**，而训练数据是**完整函数**，属于分布外样本。
  它只能用来横向比较不同模型，**不能当成绝对水平**——真正的水平看测试集 F1=0.7521。
- 三个漏报（det01/04/06）的 P 值分别是 0.39/0.13/0.47，**det01 和 det06 只差一点**
  就过线了。把阈值从默认 0.5 降到 0.3，det01 和 det06 就能被抓出来 → 8/10。
- det01（有漏洞的 `strcpy`）和 det07（安全的 `strncpy`）这对**最难的正负对**，
  模型给出的分数是 **0.3928 vs 0.2920**——**排序是对的**，只是两个都低于 0.5 阈值。
  这正说明该调阈值（见 `01` 文档 8.2 节的阈值表）。

#### B. 冒烟模型（`outputs/quickstart/best`，64 条数据 1 轮 —— 全错，这是预期的；历史 10 条版本）

用 `outputs/quickstart/best`（64 条数据、1 轮）跑检测用例：

```
与 gold 标签对比准确率: 0.4000 (4/10)
```

**4/10 是怎么来的**：模型把所有 10 条都判成 `safe`。
6 条真漏洞（det01~det06）全判错，4 条安全样本（det07~det10）全判对 → 4/10。
换句话说，它的准确率完全来自"多数类是安全样本"这个先验，**没有任何检测能力**。

用 `outputs/quickstart_cls/best`（41 类分类）跑分类用例：

| # | 期望 | 实际预测 | Top-1 置信度 | 对/错 |
|--:|------|----------|-------------:|:-----:|
| 1 | CWE-120 | CWE-77 | 0.0497 | ✗ |
| 2 | CWE-89 | CWE-77 | 0.0469 | ✗ |
| 3 | CWE-79 | CWE-77 | 0.0464 | ✗ |
| 4 | CWE-78 | CWE-399 | 0.0484 | ✗ |
| 5 | CWE-22 | CWE-77 | 0.0466 | ✗ |
| 6 | CWE-416 | CWE-77 | 0.0495 | ✗ |
| 7 | CWE-476 | CWE-89 | 0.0510 | ✗ |

**0/7**。所有置信度都在 **0.05 左右**（随机基线 1/41 ≈ 0.024），
说明模型在 41 个类别上是近似均匀乱猜——这正是没训练过的模型该有的表现。

> ✅ **这组"全错"恰恰是测试用例有效的证据**：如果没训练的模型也能答对，
> 说明用例要么太简单、要么数据泄漏了。

### 4.7 正式训练后的验收标准

做完步骤 6 的正式训练后，重新跑 4.5 的用例，按下表验收：

| 指标 | 合格线 | 说明 |
|------|-------:|------|
| 检测·CVEfixes 测试集 F1 | **≥ 0.75** | 本仓库 3 轮实测 0.7521，这是当前最好的一次。**加轮数没用**：同配置 6 轮的 `cvefixes_detection_6ep` 第 4 轮就过拟合，test F1 = 0.7490，反而略降（详见 `docs/01` §5.9） |
| 检测·合并数据测试集 F1 | 看 `results.json` | README 演示的 `merged_detection_codebert` 在阈值 0.5 下 F1 0.4848；合并数据正例率低，F1 绝对值不能与 CVEfixes 直接比 |
| （参考）跨数据集 F1 | 明显低于分布内 | 用 `data/processed/codexglue_detection_test.jsonl` 做跨源评估；泛化差距是公开难题，不要拿分布内数字去对标 |
| 检测·本用例集准确率 | **≥ 0.6** | 实测 6/10。注意这 10 条是 2~3 行的**短片段**，与训练数据的"完整函数"分布不同，只能横向比较不同模型，不能当绝对水平 |
| 分类·macro-F1 | 看 `report_test.txt` | 长尾类别会明显拉低，同时看 `weighted_f1` |
| 分类·本用例集 Top-1 | **≥ 5/7** | 这 7 类都是高频 CWE |
| 分类·Top-5 命中率 | **≥ 7/7** | 正确类别应该出现在 Top-5 里 |

**如果检测 F1 到了 0.99**，别高兴，先检查是不是划分方式错了
（按样本随机分而不是按 `group_id` 分）——见 `test_preprocess.py` 第 [5] 组断言。

**如果 F1 偏低**：先看 `results.json` 里 val F1 是否还在涨。
⚠️ **但"加轮数"这条路已经被证伪了** —— CVEfixes 检测 3 轮实测 0.7521，
同配置 6 轮的 `cvefixes_detection_6ep` 第 4 轮就过拟合、test F1 = 0.7490 反而略降
（详见 `01` 文档 §5.9、`06` 文档问题 5.2）。要提升得换方向：样本量、清洗规则、模型选型。
正式实验记得调判定阈值（见 `01` 文档 8.2 节的阈值表），阈值应在验证集上选。

**如果 F1 只有 0.6 左右**：先确认有没有误用 `--max-train-samples` 导致训练不足。

## 6. 排错手册

| 现象 | 原因 | 处理 |
|------|------|------|
| `ModuleNotFoundError: No module named 'src'` | 没设 `PYTHONPATH`，或不在项目根目录执行 | `set PYTHONPATH=%CD%` 后重新执行 |
| **`[FAIL] datasets 未安装`（但确实装了）** | `src/` 被加进 sys.path，`import datasets` 加载到项目内的同名文件 | **已修复**：`src/datasets.py` 已改名 `src/data.py`。若你从旧版本升级，手动改名即可；`check_env.py` 现在会直接指出顶替者 |
| `ImportError: attempted relative import with no known parent package` | 同上，项目内的同名文件被当成顶层模块导入 | 同上 |
| `ValueError: Unrecognized model in ...best. Should have a model_type key in its config.json` | 把训练好的检查点当基座模型传给了 `--model`，但 `best/` 里没有 `config.json` | 训练要用 `--model models\microsoft__codebert-base` 重新跑；只有推理才用 `--checkpoint .../best`。详见 `03` 文档 4.1 |
| `缺少数据文件 …\cvefixes_detection_train.jsonl` | 还没构建数据集 | 先跑 `python scripts\build_dataset.py --source cvefixes` |
| `unrecognized arguments: copy_input(char *user_input)…` | `--code` 里的 `{}` / 引号被 cmd 拆坏 | 改用 `--file demo.c` |
| ~~`ValueError: invalid literal for int() with base 10: 'CWE-120'`~~ | ✅ **已不会出现**：字符串 `label` 现在按 `cwe` 字段比对（见 4.6）。若是在更老的版本上复现，去掉 `label` 或改成数字编号即可 | — |
| `CUDA out of memory` | batch 太大 | `--batch-size 4 --max-length 256` + `gradient_accumulation_steps: 4` |
| `CrossEntropyLoss: weight tensor should be defined either for all N classes` | 分类类别数漏了 `+1`（OTHER 类） | 类别数 = 保留的 CWE 数 + 1 |
| 中文日志乱码 | 控制台代码页不对 | `chcp 65001` + `set PYTHONIOENCODING=utf-8` |
| 训练进度条里 `it/s` 只有个位数 | 在 CPU 上跑 512 token | 正常。用 `--max-train-samples 200` 先跑通流程 |
| **训练时在下载 473MB + 499MB** | `--model microsoft/codebert-base` 写的是 HF 仓库名，会去线上下载；而本地 `models/microsoft__codebert-base` 已经有同一份权重 | 改成 `--model models/microsoft__codebert-base`。已经下过的不影响使用，只是白下了约 1 GB |
| `huggingface_hub` 提示 symlinks 不支持 | Windows 未开开发者模式 | 无害，只是缓存会多占点空间。可设 `set HF_HUB_DISABLE_SYMLINKS_WARNING=1` 关掉提示 |
| Windows 上 DataLoader 多进程报错 | `num_workers > 0` | 保持 `configs/config.yaml` 里的 `num_workers: 0` |
| `transformers` 报 `AutoModel` 相关错误 | 版本太旧 | `pip install -U "transformers>=4.45"` |
| Flask 启动报 `ModuleNotFoundError: flask` | 依赖里没有 flask | `pip install flask` |
| 下载超时 / 连接被重置 | 访问 huggingface.co 慢 | `set HF_ENDPOINT=https://hf-mirror.com`，或用 `--mirror hf-mirror` |
